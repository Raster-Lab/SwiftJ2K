# Swift 6.4 feature register

Assessment date: **19 September 2026**. Applies to the independent SwiftJ2K, SwiftJLS, SwiftJXL and SwiftJLI Milestone 1 implementations. This file is mirrored across the four repositories; it creates no shared runtime dependency. Read the [upgrade evidence index](README.md), supplied manifesto and suite supplement alongside the current common contracts.

The selected compiler is **Apple Swift 6.4 (`swiftlang-6.4.0.34.1`, `clang-2100.3.34.1`)**, invoked through `/Applications/Xcode.app/Contents/Developer`. Swift **6** remains the language mode. Apple deployment floors remain **26.0**. The probe host runs macOS **27.0, build 26A428, arm64**. Compiling for macOS 26 and running on this host is **not execution on macOS 26**; minimum-OS runtime qualification remains open. Linux, native Intel and device/runtime claims require their own evidence.

## Dispositions and production scope

“Applicable” identifies an actual change or qualification requirement. “Conditional” needs a relevant use and explicit gates. “Deferred” is deliberately absent from production. “Prohibited” applies to the unsafe use identified, not to every use of the language feature. Feature availability alone does not justify a refactor.

## Installed declarations and availability evidence

The selected SDK's textual interfaces are authoritative for this execution. They do not exactly match every API name/module mentioned by the reference manifesto or moving proposal text. Preserve the supplied reference files byte-for-byte; record the differences here rather than changing them silently.

These arm64e textual interfaces were inspected alongside actual **arm64** compiler probes. The following are relevant declarations/requirements, with implementation-only annotations omitted from the presentation:

- **F01, module `Swift`:** `RawSpan.load<T>(fromByteOffset: Int, as: T.Type) -> T where T: ConvertibleFromBytes`; `OutputRawSpan.append<T>(_: T, as: T.Type) where T: BitwiseCopyable, T: ConvertibleToBytes` (line 27987). The output span is constructed with `init(buffer: UnsafeMutableRawBufferPointer, initializedCount: Int)` over exactly one two-byte sample range with initialised count zero; `consuming func finalize(for: UnsafeMutableRawBufferPointer) -> Int` (line 28185) checks the identical buffer before ending that borrow. The construction/finalisation are explicitly unsafe boundaries; the retained exclusive lease, validated slice and complete `UInt16` append justify them. These declarations are emitted into the client with availability macOS 10.14.4 / iOS 12.2 / watchOS 5.2 / tvOS 12.2 / visionOS 1.0. The explicit `Swift.ByteOrder` overloads require OS 27. Use native loading plus `UInt16(littleEndian:)` / `UInt16(bigEndian:)`, and corresponding `.littleEndian` / `.bigEndian` output conversion, under the unchanged OS 26 floor.

  The probed `MutableRawSpan.storeBytes<T>(of: T, toByteOffset: Int, as: T.Type)` has the safe `BitwiseCopyable & ConvertibleToBytes` overload and compatible availability, but it is not the production writer: constructing a mutable span over the whole destination would assume already-initialised bytes and strengthen the provider contract. The per-sample output span can initialise raw sample storage and does not read or overwrite inter-sample/prefix/row padding. Padding publication remains the provider's existing responsibility.
- **F02, module `Swift`:** `withTemporaryAllocation<T, R, E>(of: T.Type, capacity: Int, _: (inout OutputSpan<T>) throws(E) -> R) throws(E) -> R` with `E: Error`, `T: ~Copyable`, `R: ~Copyable`; the raw overload takes `byteCount`, `alignment` and an `inout OutputRawSpan` body. These are emitted into the client and have span-compatible availability. Stack placement is not guaranteed and storage starts uninitialised.
- **F03, module `Swift`, line 32835:** `UniqueArray<Element>: ~Copyable where Element: ~Copyable`, with `init(capacity:)`, `append(_:)` and `makeBorrowingIterator()`. The declaration and relevant operations require `anyAppleOS 27.0`. `_RigidArray` is internal implementation detail; no public `RigidArray`/`Containers` substitute was found.
- **F04, module `Swift`, line 33402:** `UniqueBox<Value>: ~Copyable where Value: ~Copyable`; `init(_ initialValue: consuming Value)`, `value` with `borrow` / `mutate`, and `consuming func consume() -> Value`. These require `anyAppleOS 27.0`.
- **F05, language syntax:** a value wrapper may expose stored `element` through `borrow { storage }` and `mutate { &storage }`. No experimental flag was used. These accessors cannot be mechanically added to class/actor properties, and changing an existing public accessor can break clients. See [SE-0507](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0507-borrow-accessors.md).
- **F06, module `Swift`, line 3222:** `Iterable<Element, Failure>: ~Copyable, ~Escapable`, with `makeBorrowingIterator() -> BorrowingIterator`. The installed protocol is `@available(anyAppleOS 27.0, *)`. The tested loop uses ordinary `for element in array` syntax; no speculative `for borrow` syntax is used.
- **F07, module `Swift`, lines 15601 and 19122:** `MutableRef<Value>: ~Copyable, ~Escapable` and `Ref<Value>: Copyable, ~Escapable`, respectively, both with `Value: ~Copyable` and `anyAppleOS 27.0` availability. Initialisers take `inout Value` and `borrowing Value`; `value` provides the corresponding scoped projection.
- **F08, language syntax:** an asynchronous function may use `defer { await recorder.finish() }`. The probe compiles for macOS 26 with strict Swift 6 concurrency checking; no custom library, experimental flag or unstructured cleanup task is introduced.
- **F09, module `_Concurrency`, line 3259:** the async `withTaskCancellationShield<Value, Failure>(operation:)` uses a `nonisolated(nonsending)` async throwing closure and `Failure: Error`; the synchronous overload is at line 3276. Both are emitted into the client **and** explicitly require `anyAppleOS 27.0`; client emission does not erase that requirement.
- **F10, module `Swift`, Optional section at line 16948 onward:** the installed public `map` retains its copyable-wrapped-value restriction. There are underscored ownership variants and a `take()` operation, but they are not evidence that the requested new public `ref` / `mutableRef` / `put` and consuming `map` APIs are available. Negative probes target OS 27 to distinguish missing declarations from OS-floor rejection. See the requested API design in [SE-0532](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0532-optional-noncopyable-improvements.md).
- **F13, language syntax:** `@diagnose(DeprecatedDeclaration, as: error, reason: "Test local elevation")` on a function changes the tested deprecation diagnostic from warning to error. No library linkage is needed for the attribute. See [SE-0522](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0522-source-warning-control.md).

The unique-container executable links `libswiftCore`; the async-defer executable additionally links `libswift_Concurrency` and the ordinary system/Objective-C runtime. No `Containers` package or custom compatibility library was added. This observed linkage on OS 27 is not proof of minimum-OS runtime availability. Availability-rejected APIs remain absent from production rather than guarded by a path that skips essential cleanup.
