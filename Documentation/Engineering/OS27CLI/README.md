## Implemented changes

All nine active suite package manifests, independent examples, generated validation consumers, README/migration guides and agent instructions now use the new Apple baseline. The seven shared contract files are mirrored at revision 0.4.0 with [their digest manifest](../../COMMON_CONTRACT_SHA256.txt). The owner decision supersedes OS 26 constraints in the supplied documents; the [earlier report](../Swift64/README.md), its evidence, probes, supplied manifesto/supplement and original Milestone 1 evidence remain byte-for-byte historical records.

The library now calls the OS 27 `Swift.ByteOrder` overloads of bounded `RawSpan.load` and `OutputRawSpan.append`. Public API/lease/lifetime/precision semantics are unchanged. Sample geometry/capacity checks and exact two-byte output spans still exclude padding and initialise caller-owned uninitialised sample storage. No new image allocation/copy or compatibility branch was introduced. Existing golden-byte, odd-address, padded layout, precision, cancellation and ownership tests execute against these overloads. [FEATURES.md](FEATURES.md) reassesses F01–F13: OS availability no longer blocks eligible features, but unique containers, borrowing projections and async cleanup are only adopted when there is an actual workspace or lifecycle need. Missing SDK Optional/RigidArray declarations remain missing.

The new standalone executable **swiftj2k** depends only on SwiftJ2K. It implements global/command help, version and truthful capability reporting (plain text or JSON). Reserved codec verbs report unavailability with exit 4 before opening any input/output; they do not simulate successful compression, validation or transcoding. CLI main functions stay outside library tests. The package remains free of external SwiftPM dependencies, and library-only consumers do not link the CLI. MIT licensing remains unchanged.

[CLI.md](../../../CLI.md) documents the executable and installation. `-h`, `--help`, `help [command]`, no-argument help and command-local help explain availability, syntax, defaults, examples, streams and exits. Five cumulative verbosity levels are accepted through `-v` repeats, `-vv`…`-vvvvv`, `--verbose 1`…`5`, `--verbose=+++` and `-verbose: 3`. Numeric/plus values set a level; bare flags increment. Invalid levels, quiet/verbose conflicts and invalid syntax fail with exit 2. Diagnostics use stderr; capability JSON remains clean stdout. Errors survive quiet mode; payloads, metadata, raw addresses and file paths are not logged. A closed stdout pipe returns 6 instead of a success or uncontrolled SIGPIPE termination.

[ManPages/swiftj2k.1](../../../ManPages/swiftj2k.1) is installed/updated with the matching executable by [Scripts/install-cli.sh](../../../Scripts/install-cli.sh). The installer builds release code by default or checks a prebuilt binary against VERSION, checks the manual's version header, prepares both files before replacing either, supports absolute prefixes and DESTDIR, sets modes 0755/0644 and refuses destination symlinks/directories. Each file rename is atomic; no cross-file transactional guarantee is claimed. Custom-prefix lookup uses `man -M PREFIX/share/man swiftj2k` or MANPATH. No global CLI installation was present on PATH at inventory; tests use temporary staging, not a system-wide installation. Future packaging recipes must include both files.

## Performance and supply-chain limits

[Benchmark evidence](Evidence/Benchmark) compares the preceding Swift 6.4 development source to this OS 27 change through the shared Image.swift implementation in SwiftJ2K. Both consumers target macOS 27 and use the same compiler; the dependency's prior floor was 26, so this is a source/deployment change comparison, not compiler performance. Synthetic little-endian 16-bit padded 64×63, 512×511 and 2048×2047 images receive five warmups and twenty interleaved observations per case, then a repeat using the same executables. Raw samples, median/p95/spread, checksums, thermal state, process RSS/footprint and executable sizes are retained.

First-run write median changes were +1.19%, −4.34%, +0.70%; total median changes +2.34%, +2.34%, −1.47%. A +5.58% tiny-image allocation timing crossed the pre-existing investigation threshold; the repeat changed that phase by −11.74%, so this crossing did not reproduce. Repeat write changes were +2.14%, −0.06%, +3.33%; total changes +1.53%, −0.53%, +0.20%. Process RSS/footprint rose less than 5% initially and decreased on repeat. The representative consumer executable changed from 325,328 to 324,768 bytes. Thermal raw state was 0 during both runs; frequency and scheduling were not laboratory-controlled. These measurements do not establish a general speedup. The earlier roughly 6.5% tiny-write regression against the pre-span baseline remains an open stable-release item; this follow-up comparison does not silently waive it.

Build-associated SPDX and CycloneDX generation succeeded for **both library and CLI products**, sixteen emitted files suite-wide. [Library SBOMs](Evidence/Candidate/sboms), [CLI SBOMs](Evidence/CLISBOM) and [field/provenance audits](Evidence/SBOMAudit) retain originals. The same installed generator schema-bundle issue and SPDX specVersion/externalUrl / duplicate CycloneDX identifiers remain. JSON parsing and hash checks pass; complete schema/semantic conformance is unqualified. See the [prior specification-backed audit](../Swift64/Evidence/SBOMAudit/RESULTS.md). Native SDK/runtime components are outside that SwiftPM graph. No dependency/licence or codec support claim is inferred from SBOM generation.
